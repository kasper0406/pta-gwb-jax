# M3 plan: combining the five public PTA data sets

Goal: combine NANOGrav 15-yr (NG15), EPTA DR2, PPTA DR3, InPTA DR2 and the MeerKAT PTA 4.5-yr
release (MPTA) in our own JAX pipeline. Reproduce the public five-PTA combination of Yu & Allen
(arXiv:2512.08666v3, called **YA** below) and, where the released products allow it, the
individual PTAs' published GWB results. Only then go beyond.

This is a design document. Nothing in `src/ptagwb` has changed on this branch. The inventory,
overlap matrix, PINT ingestion audit and literature summary are in
[`M3_SURVEY.md`](M3_SURVEY.md).

**Revision 2 (after independent review of 256c0be, REQUEST_CHANGES).** Changes:

1. The negative-H3 rewrite is withdrawn: zeroing H3 also zeroes the STIG design column. Signed
   H3 is now a blocking evaluator gap (Sec. 4, Sec. 8 R3).
2. ELL1H H3+H4 harmonic counts (PINT >= 7, tempo2 4) and DDH are listed as separate evaluator
   classes, aligned *before* any reference-parameter copy (Sec. 4.1).
3. A versioned YA reproduction configuration (Sec. 3.2) replaces "what MetaPulsar does":
   v0.9.3 copies the reference DM into all legs; current MetaPulsar keeps DM local. Local DM is
   a separate configuration.
4. Mandatory oracle gates for ingestion (Sec. 5.1): TOA identity, projected residuals,
   weighted column space, pointwise likelihood and gradient. All warnings are now captured.
5. Published-analysis clock/ephemeris profiles are separated from the combined profile
   (Sec. 4.2); clock files are pinned.
6. Conditional implementation checks are separated from published-model reproductions;
   parameter-dependent residual/basis terms are scoped; MPTA and InPTA are approximate
   cross-checks, not prerequisites (Sec. 6).
7. The general multi-grid GP formulation is specified (Sec. 4.3): M1's prefix identity
   (common columns = first IRN columns) does not hold with distinct spans.
8. Compute numbers are labelled as projections; the "ln BF ~ 10 implies poor overlap"
   rationale is withdrawn; F^T P F is no longer called GWB information; raw likelihood levels
   are not compared across B and C; inventory numbers are generated from the selected
   configuration.
9. The first implementation milestone is **M3a** (Sec. 5): a CPU-validated multi-leg
   container with explicit profiles and oracle gates. Sampling and evidence work are deferred.

Notation: **leg** = one PTA's data set (par + tim) of one pulsar. **K_a** = number of sampled
GP columns of pulsar a. **N_f** = number of common-process frequencies. **[UNCERTAIN]** marks
things not pinned down from the papers or the released files.

## 0. Summary

* **Selected configuration** (generated by `scripts/m3_survey.py`,
  `data/processed/m3_survey/inventory_main.json`): NG15 v2.1.0 NB, EPTA DR2new, PPTA DR3
  (GitHub fdbe6eb), InPTA DR2, MPTA: **122 pulsars, 235 legs, 61 pulsars with two or more legs,
  1,164,803 TOAs**. YA's inputs (InPTA DR1 instead of DR2): 121 pulsars, 222 legs, 56
  multi-leg pulsars, 1,090,212 TOAs (YA: 1,090,206).
* **Architecture (unchanged).** One multi-leg pulsar per physical pulsar: stacked TOAs,
  block-diagonal per-leg white noise, shared GP coefficients, and a timing design matrix whose
  columns are either shared across legs (**C**, YA) or per leg (**B**, FrankenStat). B and C
  run through the same likelihood code. (A), one leg per pulsar, is a baseline.
* **Target (unchanged): C**, because YA used it and because only shared spin/astrometry keeps
  short legs that extend past the longest leg (MPTA, InPTA) coherent with it. B is the
  robustness check. Neither is accepted before the M3a gates pass.
* **First milestone: M3a, CPU only.** Multi-leg container, explicit timing/clock/noise
  profiles, physics-preserving ingestion, generic fixed-basis GP blocks, and a small
  validation set checked against tempo2, enterprise/discovery and MetaPulsar. The NG15
  regression must pass. No sampling, no evidence work.
* **Known blockers for later stages:** signed H3 (MPTA J1825-0319), ELL1H H3+H4 harmonic count
  (10 legs), unexplained residual excess in J1600-3053 (EPTA, PPTA), PPTA J1713+0747 and
  J2241-5236. They block the affected per-PTA reproductions and YA acceptance, not M3a.

## 2. Options for overlapping pulsars

### 2.1 Our likelihood in one paragraph

Per pulsar a (M1, `likelihood.py`): r = M eps + F c + n with flat-prior timing offsets eps,
Gaussian Fourier coefficients c and white noise N. **Stage 1** (host, once): whiten with
N^-1/2, project out span(M), QR the projected basis F_p = Q_F R_F, and keep R_F,
c = Q_F^T r_p, s_perp, log|N| and log|M^T N^-1 M|. **Stage 2** (JAX, per call): square-root
absorption of the per-pulsar prior Phi_a in a batched QR, leaving the common-mode precision
E_a and score d_a; CURN is separable, HD solves one (N_psr * 2 N_f) system. In M1 the 28
common columns are the first 28 of the 60 IRN columns (same grid, same T). That "prefix
identity" is what lets one F carry both processes; Sec. 4.3 generalises it.

### 2.2 One physical pulsar with several legs

Stack the legs: r = [r_1; ...; r_P], N = blockdiag(N_p), and F = [F_1; ...; F_P] with every
leg's rows built on the **same** frequencies and time origin (DM/chromatic blocks carry the
per-TOA factor (nu_ref/nu)^beta). Sharing a pulsar's GP coefficients across legs is exactly
"stacked TOAs, block-diagonal noise, shared basis". The timing design matrix is the only
modelling choice:

* **per-leg (B):** M = blockdiag(M_p), so P = blockdiag(P_p) and the stage-1 contractions add:
  A = sum_p R_p^T R_p, b = sum_p R_p^T c_p, r^T P r = sum_p (s_perp,p + |c_p|^2), and the
  log-determinants add. In square-root form, QR the stacked factors [R_1; ...; R_P] = Q R and
  take c = Q^T [c_1; ...] with s_perp from the orthogonal complement (no subtraction). This is
  FrankenStat (arXiv:2512.14807, eq:franken-N/M).
* **shared (C):** M has shared columns for astrometry, spin and binary parameters (and, in the
  YA configuration, DM/DM1/DM2; Sec. 3.2) plus per-leg detector columns (phase offset,
  backend JUMPs, FD). Stage 1 is one joint QR per pulsar on the stacked whitened TOAs. Shared
  columns require **every leg's residuals to be computed at one common nominal model**: with
  each leg's own values, the offsets M_p (beta_ref - beta_p) are not in the span of the
  shared columns. YA copy the reference PTA's values into the other legs' pars and recompute
  residuals. Before the copy, every leg must be on the **same evaluator conventions** (Sec.
  4.1); otherwise the copied values mean different delays in different legs.

Stage 2 sees one (R_F, c, s_perp) per pulsar in both cases, so its per-call cost depends on
K_a and N_psr only.

### 2.3 Option (A): one leg per pulsar (Lite, arXiv:2503.20949v2)

FoM = sqrt(T_obs / (<sigma>^2 <Delta t>)^(3/13)) picks one leg per pulsar; every leg keeps its
released model. Valid and cheapest, but loses information: on IPTA DR2, Lite's log10 B(CURN /
noise) was 3.0 against 9.1 for the full combination, its 95 % (A, gamma) area 2.25x larger and
A(13/3) 23 % high (tab:crn_params). Use: baseline and cross-check.

### 2.4 Option (B): per-leg timing model, shared GP coefficients (FrankenStat)

Valid but conservative: it marginalises over more timing directions than the physics has. The
FrankenStat validation (OS S/N 11.23 combined vs 11.14 FrankenStat) used three PTAs that each
cover the full 20 yr with interleaved TOAs; it does not test legs with staggered spans. For an
MPTA leg extending 3 yr past NG15, per-leg F0/F1 and astrometry remove that leg's lowest
frequencies. Mixed DM treatments (DMX in one leg, a shared DM GP) are consistent but wasteful.
Engineering is minimal: each leg keeps its own model, so no value copy is needed.

### 2.5 Option (C): TOA-level combination with shared astrophysical columns

Same marginalised likelihood as a manual IPTA-style combination, under the linear-timing
assumption, provided (i) every leg is evaluated with the same delay conventions (Sec. 4.1),
(ii) each leg stays linear around the copied reference values, and (iii) legs are
phase-connected (YA fixed early phase disconnections by adding pulse numbers). These are
checked by the M3a gates, not assumed.

### 2.6 Comparison

| | (A) Lite | (B) per-leg M | (C) shared M |
|---|---|---|---|
| Pulsars / legs used (selected configuration) | 122 / 122 | 122 / 235 | 122 / 235 |
| Timing columns | leg's own | blockdiag per leg | shared astrophysical + per-leg detector |
| Low-frequency information from staggered legs | none | reduced (to be quantified) | kept |
| Par-file engineering | clock/ephem profile | clock/ephem profile | + common evaluator profile, value copy, DM model |
| Stage 1 (host, once) | per leg | per leg, then aggregate | joint per pulsar |
| Reproduces YA | no | no | yes, with the Sec. 3.2 configuration |
| Main risk | single-leg systematics | conservative; mixed DM | evaluator parity, linearity, phase connection |

How B and C will be compared: by **likelihood shapes** in the common-process parameters at
fixed, identical noise, and by the **fixed-covariance information on the GWB amplitude**,
I_AA = (1/2) tr[(C^-1 dC/dA)^2] at a fiducial point, per frequency, plus small staggered-span
injections (Sec. 5.1). Not by raw likelihood levels: with flat timing priors of different
dimension, the absolute likelihood constants of B and C are arbitrary and are not evidences.
(F^T P F, the information about the Fourier coefficients themselves, is a useful diagnostic
but is not the GWB information.)

### 4.2 Clock and ephemeris profiles

Two kinds of profile, never mixed:

* **Published-analysis profile** (per PTA, for reproductions): the clock realisation and
  ephemeris the published analysis used. NG15: TT(BIPM2019), DE440, release clock files.
  EPTA DR2: TT(BIPM2021), DE440, the release's corrected Nancay clock file
  (`EPTA-DR2/clockfiles/ncyobs2obspm.clk`; PINT's current global file agrees with it to
  <= 3.1 ns, rms 0.1 ns, over DR2new, but we pin the release file). PPTA DR3: TT(BIPM2020)
  from the par, **DE440** (the GW paper's override; the par says DE436), the release's
  `pks2gps.clk`. InPTA DR2: TT(BIPM2023), DE440. MPTA: **[UNRESOLVED]** the pars say
  TT(BIPM2020) (81 of 83), the paper says TT(BIPM2022). Over the MPTA span the two differ by
  4.3 ns rms (11 ns peak to peak, mean removed). Default to the par value (it is what the
  released timing model was fitted with), run BIPM2022 as a variant, and report both.
* **Combined profile** (for B/C and YA): one clock realisation for all legs (proposed
  TT(BIPM2023), the latest that covers every TOA) and DE440. Every observatory clock file is
  pinned by hash in the manifest rather than taken from the global repository at run time.
  The survey records PINT clock warnings per leg (e.g. "Data points out of range in clock
  file 'leap2effix.clk'" for EPTA legs); each must be resolved or explained.

### 4.3 General GP formulation with distinct grids

Per pulsar, the GP basis is a concatenation of blocks

    F_a = [F_IRN | F_DM | F_chrom | F_band | F_sys | F_SW | F_HFF | F_common | ...],

each block with its own frequency grid (spacing 1/T_block and count), time origin, per-TOA
scale (nu_ref/nu)^beta or solar-wind geometry factor, row mask (band, system) and PSD
normalisation (strain-type A^2/(12 pi^2) f_yr^(gamma-3) f^-gamma / T; TempoNest DM
normalisation for EPTA files; solar-wind density units). The prior is block diagonal,
Phi_a = blockdiag(Phi_block). Consequences:

* **The prefix identity breaks.** When the common grid equals the first N_f IRN frequencies
  (M1, YA with T = array span), the two blocks share columns and their variances add. When
  they differ (EPTA, PPTA, MPTA and InPTA single-pulsar models use per-pulsar spans; the
  common process uses the array span), F_common and F_IRN are distinct, nearly collinear
  blocks. The stage-1 contraction must then keep all columns and their cross-terms
  (A = F^T P F over the full block set), and stage 2 must absorb Phi over the non-common
  blocks while keeping the common block for the inter-pulsar solve. The lam0-split of M1
  carries over (lam0 phi_CP is absorbed on the common block only).
* **Conditioning.** Distinct but nearly identical grids (e.g. per-pulsar 19.1 yr vs array
  20.1 yr) make A nearly singular. The square-root (QR) path tolerates this; a test with
  deliberately close spans checks it.
* **Fixed blocks** (hyperparameters held at released values) are absorbed in stage 1 into an
  effective noise covariance (Woodbury in square-root form), so they cost nothing per call.
* **Sampled blocks** set K_a. K_a = 60 + 200 = 260 holds for the YA configuration (30 IRN +
  100 DM bins on one grid). It is **not** a bound: sampled PPTA models (RN T_p/240 d, DM
  T_p/60 d, HFF T_p/30 d, band and SW blocks) reach several hundred to ~1,000 columns for the
  longest pulsars.
* **Overlapping selections.** PPTA's band, broadband and group ECORRs overlap per TOA. They
  are additive covariance terms (an ECORR "basis GP" with one column per epoch and
  selection), not disjoint epoch blocks as in `noise.WhiteNoise`.
* **Validation:** a dense small-system oracle (explicit covariance, unequal spans, two
  pulsars, three legs, overlapping ECORR selections, distinct grids) against which the
  square-root implementation must agree to the M1 tolerances.

**M3a revision (review minor #4).** The exit criterion above is replaced by mechanically
decidable conditions E1-E8 (`docs/M3A_VALIDATION.md` Sec. 10):
* E1: every loadable leg passes G1/G2.
* E2: G5 dense and real-system oracles pass.
* E3: G9 passes.
* E4: B/C reproduce MetaPulsar v0.9.3.

* E6: G8 passes for A/B/C.
* E7: G6 within the numeric bound.

The **G6 bound** is a likelihood-shape difference <= 0.1 nats over 20 random hyperparameter
points, a whitened linearisation residual <= 0.1, and a column-space sine <= 1e-3. The swap holds
CLOCK/EPHEM and the free-parameter set fixed.

requirement. Legs failing E8 are *not* quarantined wholesale, because that would make E8 pass
vacuously; they are simply not admitted to comparisons with published numbers. Status

### 5.2 M3b: per-PTA checks

Two different kinds of check, never confused:

* **Conditional implementation checks** (any PTA): fix all non-target noise at released
  values and compare our likelihood/posterior with enterprise run on the **same** conditional
  model. This validates code, not published numbers.
* **Published-model reproductions** (only where the full model and products exist): EPTA
  DR2new (custom RN/DM/SV, J1713 dips, 9 common modes; target BF(HD/CURN) = 60, HD log10 A =
  -13.94 (+0.23/-0.48), gamma = 2.71 (+1.18/-0.71); chains Zenodo 8091568) and PPTA DR3 (full
  model including sampled dips, HFF, band, group and SW terms, tailored priors, 27 common modes
  from the released builder; CURN log10 A = -14.50 (+0.14/-0.16), gamma = 3.87 +- 0.36; chains
  on GitHub). A conditional (fixed non-IRN noise) posterior is **not** expected to match these
  chains within MC error.
* **Approximate cross-checks** (not prerequisites for any combination work): MPTA (noise from
  rounded paper tables and unofficial scripts; ER CURN log10 A = -14.25 (+0.21/-0.36), gamma
  = 3.60 (+1.31/-0.89); DATA HD -14.28 (+0.23/-0.30)) and InPTA DR2 (no released WN values;
  95 % upper limit log10 A < -13.47, uniform-A prior).

Blocking legs for M3b acceptance of the affected PTA: J1600-3053 (EPTA, PPTA), PPTA
J1713+0747, PPTA J2241-5236, until G3-G5 pass for them.

### 5.3 M3c: YA reproduction (GPU; needs approval)

## 6. Scope of published-model support

### 6.1 Parameter-dependent residuals and bases

| Feature | Where | Status in our design |
|---|---|---|
| Fixed GP hyperparameters | all | stage 1 (L5) |
| Sampled power-law GPs on fixed bases | all | stage 2 (L6) |
| Sampled deterministic events (epoch, amplitude, timescale, chromatic index) | PPTA (dips), EPTA J1713 (fixed index), MPTA (Gaussian, annual) | per-call residual update for those pulsars (TOA-level work); implement only for PPTA/EPTA reproductions |
| Sampled chromatic index (basis depends on the parameter) | InPTA (free chromatic), MPTA (fitted beta) | per-call basis rebuild for those pulsars, or fixed at the released value as a conditional check |
| Finite-prior solar-wind density | PPTA, MPTA, InPTA | Gaussian-prior column or sampled parameter, not a flat timing column |

### 6.2 What "reproduction" means per PTA

EPTA and PPTA: full published model, compared with released chains. MPTA and InPTA:
approximate cross-checks, because the products needed for an exact configuration (machine-
readable noise models, WN values, priors) are not released.

### 6.3 YA white-noise refit

YA fitted WN with the RN and DM model present. Our refit maximises the joint posterior over
WN, IRN and DM hyperparameters per multi-leg pulsar (with the common process absent, as in
their single-pulsar stage), from several starting points; the spread of the optima is reported.
Importing released per-PTA WN values is only a diagnostic shortcut.

## 7. Compute (all numbers are projections until measured)

Measured anchors (`docs/PERF.md`, RTX 5090, float64): NG15 HD (67 x 28 = 1876 common
dimensions, K = 60) value+gradient 15.0 ms production / 8.8 ms fast at B = 1, 4.4 ms per chain
at B = 16. M2 HD^13/3: ~3e5 chain-gradients, 61 min.

Projected scaling: the common Cholesky grows by ~5.9x from 1876 to 3388 dimensions (121 x 28);
the per-pulsar cubic work grows by ~147x from (67, K = 60) to (121, K = 260). On these
assumptions a YA-fidelity HD value+gradient is ~60-150 ms and an HD NUTS run ~10-35 GPU hours;
a configuration with fixed DM hyperparameters (K = 60) ~25-45 ms per call. These are plausible
but unmeasured, and neither the NUTS cost (step counts, funnels in 121 x 2 amplitude pairs) nor
the batched memory footprint follows from them.

Before any GPU commitment: benchmark forward and backward throughput **and memory** at
K in {60, 120, 260} and N_psr = 122 (CURN and HD, B = 1/4/16), start with deterministic checks
and CURN, and diagnose reweighting overlap before buying an evidence ladder. Reduced-fidelity
runs (fixed DM, fewer DM bins) are useful diagnostics but change the target. No overall GPU
budget is committed in this plan.
